# Rust 语义修复设计与验证

这轮修复针对 `df2d5b1` 的真实迁移回归。六组对照使用基线 `78db22d` 相同的 `.lay` 字节和图像资源；原失败产物保存在本地 `release/history/df2d5b1/`，源码和当时验收记录仍可从 Git 读取。

## 底层库与职责

- `contour = 0.13.1`，关闭默认功能；未启用 `f32` 或 GeoJSON，实际 `Float` 为 `f64`。其 D3 来源只说明算法来源，兼容性由本项目夹具验证。
- LayMesh 保留阈值、采样中心偏移、非均匀网格映射、缺失单元遮罩和极坐标周期规则。`contourf` 以相邻超水平集合之差生成色带，最后一带保留最高阈值以上区域；保留孔洞，避免半透明区域重复叠色。
- `kurbo` 保留解析曲线与描边；`i_overlay` 完成布尔运算和放大极坐标纹理的直线裁剪。
- `image` 负责格式解码，`moxcms 0.8.1` 完成 ICC 到 sRGB。JPEG 的 CMYK/YCCK 原始采样通过同一依赖树的 `zune-jpeg`/`zune-core` 读取，避免在 ICC 应用前丢失 CMYK 分量。保留 alpha，先完成色彩转换，再处理方向及裁剪。TIFF 的元数据读取先于解码限额配置，以兼容该版本解码器。
- `fontdb`、`rustybuzz`、Unicode 和 RaTeX 继续共用原生/WASM 路径。第三方库类型不进入公开接口。

许可证和精确版本记录于 `Cargo.lock`、`release/licenses/manifest.json`。应用发行包不包含测试字体或正文字体。

## 已恢复的上层契约

实例身份与锚点定义随分组重排保留；不再用坐标相等猜测引用。命名实例按原规则分配 `name`、`name#2` 等身份，独立放置使用 `@1`、`@2`，不受未放置素材数量影响。路径自己的 `border_*` 不再附加容器矩形边框；融合默认没有额外描边。长度别名 `in` 恢复。

图例保留线、marker、误差方向、填充及 hatch，恢复默认样本尺寸和间距。轴文本显式颜色和继承规则分开处理。阶跃默认为 post；area 使用逐行 baseline；缺失采样行在 marker、误差和颜色维度一致处理。分箱、ECDF、角度单位、对数刻度等规则由兼容测试固定。

RaTeX DisplayList 的实线 y 坐标是线中心；转换到矩形时减去半厚度。公式的 em 到毫米换算、inline/display 风格保持库原生值。最终 shaping 后重新检查宽度；字体嵌入限制在选择前处理并警告。空心 marker 的逐点透明度数组覆盖标量默认，避免 0.5 被重复相乘成 0.25。

极坐标路径、孔洞、轴/grid 圆弧及裁剪保留数据配方；分组缩放后按最终物理变换重新细分。极坐标 hatch 同样重新裁剪，不能只放大早期截断的端点。数值测试使用含旋转和非均匀缩放的最终坐标，检查 0.001 mm 误差，并移除配方作为故障注入对照。此为针对性数值验证，不宣称对所有浮点极限输入的形式化误差证明。

语言服务共用不执行程序的 LCSS 校验，恢复参数、单位、class、返回类型与本地化契约。LSP 中未保存缓冲区优先于磁盘；关闭及文件变化后恢复依赖状态。浏览器根据编译缺失资源按需加载已注册资源，保留编辑错误后的上次预览，并单独测量资源、编译和 SVG 输出时间。

## 验证方式

`legacy-assertions.json` 从旧 183 个测试的语法树提取 **891 个断言调用点**，包含辅助函数及循环上下文。数字不是动态断言执行次数。`assertion-maps/` 将每个调用点关联到新的具体行为测试；循环参数在对应测试中保留。

`python scripts/test-contracts.py --offline` 运行 Rust 与 Python 测试并检查映射和执行证据。编译输入回放、逐断言端口、Scene 数值比较、真实编辑流程和产物审计分别统计；任何一种单独通过都不代替其他验收。

Scene 比较对合同字段缺失、非数值变化和文字颜色失配失败；旧 Scene 从未提供的可选字段不被当成缺失合同。分组表示变化通过实际物理位置/路径检查归一化，不用删除失败断言消除差异。图例和绘图顺序由专门的组合样式及层顺序断言覆盖。

PNG 保留尺寸和 pHYs；PDF 使用 Poppler 独立像素检查及文本提取；SVG 检查矢量和公式源码。真实浏览器与 VS Code 测试覆盖编辑状态变化。最终运行次数、通过数量、版本、SHA-256、性能和平台范围以 `delivery.json` 与 `README.md` 的交付记录为准。

## 允许的外观或存储差异

- RaTeX/KaTeX 与 MathJax/NewCM 的字形、笔画和度量不同。没有人为放大公式或把公式转换为位图；网页使用 SVG 优先展示。
- 正文来自系统或用户字体；实际比较另有嵌入字体字节及字体表审计。Noto 集合提取的签名、校验和或共享 CFF 名称变化，不等于字形、cmap 或排版度量变化。
- 已验证的圆帽/融合解析边界保持数学圆弧，不复刻旧近似曲线的 0.089258 mm 外凸。
- 当前平台实际验证范围必须在交付报告中列明；保留其他平台构建目标不等于已经在那些平台运行。
