# LayMesh 0.7.1

## 中文

0.7.0 候选未发布：发行测试清空 `PATH` 后，新增媒体示例无法找到 FFmpeg。0.7.1 为五平台安装测试显式准备并配置 FFmpeg，并将演讲者计时测试改为等待实际状态更新；媒体功能代码保持一致。

本版将视频、音轨和跨页背景音乐接入主线，并新增内嵌媒体的多页 PowerPoint 导出。

- 新增 `video()`、`audio()` 及页面、步骤、文档的 `.play()`。支持延迟、片段裁剪、循环、音量、静音和视频点击播放。每个视频实例具有独立播放状态及封面。
- VS Code、网页预览与放映共用视频控件，支持播放、暂停、拖动进度和音量调节。翻页停止页内媒体并保留背景音乐，菜单、后台暂停与退出放映正确管理播放和资源。
- 视频替换、音轨文件和背景音乐参数修改会更新原生/WASM 增量预览；同一素材共享数据，保留主线的手动开始放映、页面复用、警告显示与 PDF 导出行为。
- 离线 HTML/ZIP 内嵌媒体与运行时；MP4 混合视频原声、页内音轨及文档音乐。首版支持 H.264 MP4、MP3、WAV，原生宿主保留 M4A 兼容处理。
- `.laydoc` 默认导出一份完整 PPTX，内嵌并去重视频、音轨和封面，普通文字与图形仍可编辑。CLI、Python、VS Code 和离线 HTML 导出入口保持一致；`--page` 选择单页，`--all-pages` 保留逐页文件输出。
- PPTX 映射自动、点击及步骤启动规则，支持延迟、片段裁剪、循环、音量、静音和首张幻灯片启动的跨页音乐。视频保留位置、尺寸、矩形裁剪、旋转及镜像；不能映射的特效给出警告并保留可播放视频。整本导出要求各页尺寸一致，错误时保留原目标文件。

**验证边界：** 已完成媒体与增量预览回归、三浏览器播放、真实 Linux VS Code、混音导出、PPTX 结构和 Microsoft Open XML SDK 校验。Linux WebKit 视频检查使用 GTK 窗口模式。Windows Microsoft 365 PowerPoint 的实际播放、无修复提示、裁剪/循环、跨页音乐及保存重开仍待实机验收；本版不承诺 macOS PowerPoint、WPS 或 LibreOffice 的媒体兼容性。普通对象动画和页面转场继续按静态 PPTX 导出。

[使用说明与 Windows 验收步骤](https://muxkin.github.io/LayMesh/docs/topics/media.zh-CN.html)。VS Code Marketplace 仍由发布者手动上传；GitHub Release 提供五个平台的 VSIX、Python wheel 和校验和。

## English

The 0.7.0 candidate was not published: media examples could not find FFmpeg after the installed-wheel test cleared `PATH`. Version 0.7.1 explicitly prepares and configures FFmpeg for five-platform installation checks, and waits for an actual presenter timer update in the browser regression. Media implementation code is unchanged.

This release integrates video, audio tracks and continuous document music, and adds multi-page PowerPoint export with embedded media.

- Add `video()`, `audio()` and page, step and document `.play()` bindings, with delay, trimming, looping, volume, mute and video click playback. Each video instance keeps its own playback state and poster.
- Share video controls across VS Code, web previews and presentations. Page navigation stops page media while preserving document music; menus, background pause and presentation exit manage playback and resources.
- Invalidate native/WASM incremental previews when media files or music settings change, share repeated media data, and retain manual presentation startup, page reuse, diagnostic handling and PDF behavior.
- Bundle media and runtime in offline HTML/ZIP; mix video sound, page tracks and document music in MP4 exports. Initial formats are H.264 MP4, MP3 and WAV, with native-host M4A compatibility processing.
- Export an equal-size `.laydoc` as one complete PPTX by default, embedding and deduplicating video, audio and posters while keeping ordinary text and shapes editable. CLI, Python, VS Code and offline HTML exports share this behavior; `--page` selects one slide and `--all-pages` retains numbered single-slide outputs.
- Map automatic, click and step playback to native PPTX timing, including delay, trimming, looping, volume, mute and first-slide music across slides. Preserve video placement, size, rectangular crops, rotation and reflection. Warn on unsupported effects while retaining playable video; reject mismatched slide sizes without replacing the destination.

**Verification boundary:** Media and incremental-preview regressions, three-browser playback, actual Linux VS Code, audio mixing, PPTX packaging and Microsoft Open XML SDK validation have passed. Linux WebKit video checks use GTK window mode. Actual Windows Microsoft 365 PowerPoint playback, repair-free opening, trimming/looping, cross-slide music and save/reopen still require device verification. This release does not promise media compatibility with macOS PowerPoint, WPS or LibreOffice. Ordinary object animations and page transitions retain static PPTX export behavior.

[Usage and Windows acceptance checklist](https://muxkin.github.io/LayMesh/en/docs/topics/media.html). Marketplace upload remains manual; GitHub Release provides five-platform VSIX packages, Python wheels and checksums.
