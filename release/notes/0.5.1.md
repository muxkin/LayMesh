LayMesh 0.5.1 combines filled shape arrows and anchor integration with the formula-rendering improvements made since 0.5.0.

## What's new

- Create reusable filled arrows with `arrow()`, `arrow.arc()`, `arrow.bent()`, `arrow.uturn()`, `arrow.chevron()` and `arrow.path()`. Namespace completion, signatures and hover share the API registry.
- Connect the final arrow endpoints to physical coordinates, layout anchors, chart data points or selected path anchors. Per-end offsets, single-anchor placement, material reuse and group reflow follow existing placement rules.
- Set shaft width with a constant, a start/end pair or an arc-length profile. Start and end heads can have independent length and width; chevrons remain single-headed.
- Curved arrows use straight triangular heads centered on shaft-end tangents. Custom paths retain the complete source curve; arc sweep includes the tangent heads. Anchor solving includes head lengths and reports impossible constraints or intersecting outlines.
- Apply solid, gradient, hatch and image fills, outlines, opacity, shadows and glow to one closed silhouette. SVG/PDF preserve vector subjects; PPTX preserves supported editable geometry and reports local raster fallback for unsupported paints or effects.
- Fix PPTX `contain` image fills losing their empty margins in LibreOffice. The exported shape retains editable geometry and an independent image resource.
- Improve OpenType math-font layout, multilingual formula text shaping, chemical bonds, nested math alphabets and vector placeholders for missing glyphs. Expand the formula gallery and regression corpus, pin the RaTeX fork revision, and preserve absolute fixture font paths on Windows.
- Include the GitHub draft-publication fix and refreshed bilingual documentation, examples and previews.

## Compatibility

`arrow()` now creates a filled shape. Line arrows use `line(..., end_head=head(...))`. Automatic migration only handles calls identifiable by line-only parameters and valid for `line`; old calls containing only shared geometry such as `length/angle` or `dx/dy` are ambiguous and require manual review. User-defined functions named `arrow` retain normal shadowing behavior.

For `arrow.arc()`, `radius` is the shaft centerline radius and `sweep_angle` includes both heads. For `arrow.path()`, heads extend beyond the source curve; `start/end` anchor placement aligns the final tips. `.centerline` includes head axes, while `.path` remains the closed silhouette. Unsatisfiable geometry is diagnosed instead of silently changing dimensions.

## Distribution and verification

Python, Rust and VS Code share version 0.5.1. Stable wheels and VSIX packages cover Windows x64, Linux x64/ARM64 and macOS Intel/Apple Silicon. The release workflow audits all ten packages and their `SHA256SUMS`; PyPI approval precedes upload and GitHub Release creation. Marketplace uploads remain manual.

Arrow regression checks cover anchors, unequal heads, variable width, native/WASM parity, SVG/PDF/PNG/PPTX exports and LibreOffice round-trips. LibreOffice verification is separate from native Microsoft PowerPoint testing. Cross-platform results and published artifacts are recorded in the [release workflow](https://github.com/muxkin/LayMesh/actions/workflows/publish-pypi.yml).

See the [arrow guide](https://muxkin.github.io/LayMesh/en/docs/topics/arrows.html) and [export guide](https://muxkin.github.io/LayMesh/en/docs/topics/export.html).

## 更新内容

- 新增六种可复用形状箭头：`arrow()`、`arrow.arc()`、`arrow.bent()`、`arrow.uturn()`、`arrow.chevron()`、`arrow.path()`；命名空间补全、签名和悬停共享 API 登记表。
- 最终端点可连接物理坐标、布局锚点、图表数据点及已选定的路径锚点；支持两端偏移、单点锚定、素材复用和组内重新布局。
- 箭身宽度可用固定长度、首尾宽度对或沿弧长的控制点列表定义；两端头部长宽可独立设置，燕尾模板仍限单头。
- 曲线箭头的直边三角头居中连接箭身末端切线。自由路径保留完整原曲线；圆弧总扫角包含头部。锚点求解计入头部长，无法满足的约束及自交轮廓明确报错。
- 统一闭合轮廓支持纯色、渐变、花纹、图片填充、边框、透明度、阴影和发光。SVG/PDF 保留矢量主体；PPTX 保留支持的可编辑几何，对无法原生表达的填充与效果提示局部栅格回退。
- 修复 PPTX 的 `contain` 图片填充在 LibreOffice 中丢失留白的问题，保留可编辑形状和独立图片资源。
- 改进 OpenType 数学字体、多语言公式文字排版、化学键、嵌套数学字母及缺字矢量占位；扩充公式画廊和回归语料，固定 RaTeX fork 修订，并修复 Windows 绝对字体路径处理。
- 纳入 GitHub 草稿发布修复，同步中英文文档、示例和预览。

## 兼容性

`arrow()` 现在创建形状箭头；线条箭头使用 `line(..., end_head=head(...))`。自动迁移仅处理能由线条专属参数识别、且参数适用于 `line` 的旧调用。只有 `length/angle` 或 `dx/dy` 等公共几何参数的旧调用无法自动判别，需要手动检查。用户定义的同名 `arrow` 函数仍遵循正常遮蔽规则。

`arrow.arc()` 的 `radius` 表示箭身中心线半径，`sweep_angle` 包含两端头部。`arrow.path()` 的头部沿原曲线向外追加，使用 `start/end` 时对齐最终箭尖。`.centerline` 包含头部轴线，`.path` 仍表示闭合形状轮廓。无法满足的几何约束会报错，不会静默修改尺寸。
