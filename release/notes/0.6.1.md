LayMesh 0.6.1 fixes VS Code preview and presentation resource loading failures that could leave even a minimal layout blank on Windows and Linux.

## Fixes

- Load Rust WASM, CanvasKit WASM and drawing resources in the owning webview, then transfer their bytes to Canvas workers. Workers no longer request these files through VS Code's local-resource proxy, avoiding HTTP 408 errors and Canvas worker timeouts.
- Apply the same initialization to embedded presentation playback and preserve the existing browser rendering path.
- Report resource and rendering failures as preview errors, with refresh guidance, instead of labeling them as source errors or offering an irrelevant source jump.

## Validation and distribution

Real VS Code regression checks cover blocked worker resource requests, images and formulas, editing, presentation playback, multiple preview panels and reopening a panel. A Linux installed-VSIX recording also verifies the minimal line example and a full scientific layout.

Python, Rust, runtime metadata and VS Code share version **0.6.1**. The release workflow builds and audits five wheels and five stable VSIX packages for Windows x64, Linux x64/ARM64 and macOS Intel/Apple Silicon. PyPI retains its approval gate; GitHub Release uses the same reviewed artifacts and SHA-256 checksums. Marketplace upload remains manual.

LayMesh 0.6.1 修复 Windows 和 Linux 上 VS Code 预览及放映的资源加载失败；此前即使简单布局也可能出现空白预览。

## 修复内容

- 在所属 webview 内加载 Rust WASM、CanvasKit WASM 与绘图资源，再将字节传递给 Canvas worker。worker 不再通过 VS Code 本地资源代理请求这些文件，避免 HTTP 408 错误和 Canvas worker 超时。
- VS Code 内嵌放映采用相同的初始化方式，并保留网页端现有绘制路径。
- 将资源加载和绘制失败正确显示为预览错误，提示刷新重试，不再误报为源码错误或提供无关的源码跳转。

## 验证与发行

真实 VS Code 回归覆盖 worker 资源请求被阻断、图片与公式、编辑更新、演示放映、多预览面板和关闭重开；Linux 安装版 VSIX 录屏验证了简单线条示例与完整科研布局。

Python、Rust、runtime 和 VS Code 统一版本号 **0.6.1**。发布工作流为 Windows x64、Linux x64/ARM64、macOS Intel/Apple Silicon 构建并审计五个 wheel 和五个正式版 VSIX。PyPI 沿用审批门禁，GitHub Release 使用同一批审核包和 SHA-256 校验和；Marketplace 继续手动上传。
