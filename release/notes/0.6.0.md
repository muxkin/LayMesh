LayMesh 0.6.0 adds multipage presentations and CSS animation, and moves native and browser drawing to Skia while preserving physical layout, text shaping and export interfaces.

## What's new

- Compose independent `.lay` pages with `.laydoc`. Preview the selected page, edit unsaved dependencies, and export complete or selected pages without recompiling the document during playback.
- Import unmodified Animate.css **4.1.1** and use all **97 effects** through their original class names. Standard keyframes, animation properties, variables, easing, media conditions and the six nonplanar effects share Rust/WASM sampling. This is a defined compatibility target, not a claim to implement all browser CSS.
- Sequence steps with `start="click"` or `start="after-previous"`. Within a step, actions support `start="step"`, `"with-previous"` and `"after-previous"`, together with per-action timing overrides. Finished exit and displacement animations retain their sampled terminal state in presentation holds; normal static layout remains complete.
- Start when the first page is ready, while later pages prepare in the background. Web and VS Code preparation use bounded compiler pools; editing previews take priority. Pending page changes keep the current picture and stop the clock until the target frame is ready. Preparation builds resources directly, without rehearsal or timed warmup.
- Present inline in VS Code or fullscreen in a browser. Navigate with click, wheel and keyboard; use the right-click menu for pages, automatic playback, speed, seeking, black/white screens and help. Controls default to hidden and appear with **Tab**; choose always visible, bottom-position hover, or hidden. Diagnostics use popovers and preserve the last successful preview. Exit/reopen cleans up asynchronous work; the test page displays a compact summary while retaining full downloadable statistics.
- Export **MP4/GIF** with FFmpeg, or PNG snapshots at a selected time/step. Defaults are 1920px/30fps for MP4 and 960px/20fps for GIF; encoding streams frames with bounded memory and cleans up cancelled/failed output. FFmpeg must be available on PATH. Audio and native PowerPoint animation are not included.

## Rendering and compatibility

Web and VS Code use the pinned CanvasKit 0.42.0 standard build, preferring Worker/OffscreenCanvas and WebGL2. Retained resources and property updates replace full-frame RGBA transport during GPU playback. The requested resolution and effects are preserved; cache pressure does not reduce quality. Main-thread and Skia software fallbacks remain available, including offline VSIX operation.

Native rasters use Skia CPU and PDF pages use SkPDF. A version-pinned PDF compatibility pass preserves original 16-bit color/alpha samples, exact page dimensions and ActualText for formulas/artistic text. SVG and editable PPTX retain their format-specific vector serializers. Layout and glyph selection remain in Rust; ordinary static export does not run animation. The old Vello CPU and krilla runtime dependencies have been removed.

## Validation and distribution

Regression coverage includes the 97-effect browser reference, a 32-page academic deck with charts/formulas, first playback, navigation/cancellation/retry, progressive preparation, fixed document versions, native PDF image precision/text semantics, and actual VS Code previews. CI runs native tests across Windows, Linux and macOS, browser regressions, and five-platform wheel/VSIX audits.

Performance reports distinguish compiler preparation, resource construction, drawing submission, completion estimates and page-transition waits. A 3840×2160 buffer does not establish physical display presentation. Integrated-GPU **4K60 remains unverified**; software-GPU tests and discrete-GPU measurements do not constitute that acceptance.

Python, Rust and VS Code share version **0.6.0**. Windows x64, Linux x64/ARM64 and macOS Intel/Apple Silicon packages are built and audited together. PyPI publication uses the existing approval gate; GitHub Release receives those same reviewed assets and checksums. Marketplace upload remains manual. Current results are recorded in the [release workflow](https://github.com/muxkin/LayMesh/actions/workflows/publish-pypi.yml).

See the [animation guide](https://muxkin.github.io/LayMesh/en/docs/topics/animation.html) and [document guide](https://muxkin.github.io/LayMesh/en/docs/topics/documents.html).

LayMesh 0.6.0 新增多页演示与 CSS 动画，将原生、网页和 VS Code 绘制统一到 Skia，保留物理排版、字体选择和现有导出接口。

## 新功能

- 使用 `.laydoc` 编排独立 `.lay` 页面，支持选页预览、未保存依赖、全文或选页导出；放映期间不重新编译文档。
- 原样导入 Animate.css **4.1.1**，通过原类名使用全部 **97 个动画**。关键帧、动画属性、变量、缓动、媒体条件及六个非平面效果共用 Rust/WASM 采样；不据此宣称兼容全部浏览器 CSS。
- step 支持 `start="click"` 与 `start="after-previous"`；同一步中的动作支持 `"step"`、`"with-previous"` 和 `"after-previous"`，以及单次参数覆盖。退出与位移动画在放映停留时保持边界状态，普通静态排版仍显示完整内容。
- 首页就绪即可放映，后续页面后台准备。网页和 VS Code 使用有界多核编译队列，编辑预览优先。目标页未准备好时保留当前画面并暂停计时；直接构建资源，不通过预播或固定时长预热建立缓存。
- 支持 VS Code 内嵌放映和浏览器全屏、点击/滚轮/键盘导航、右键菜单、自动播放、倍速、时间定位及黑白屏。控制栏默认隐藏，**Tab** 呼出，右键可选一直显示、鼠标到位置显示或不显示。错误使用浮层，保留上次成功画面；退出清理异步任务，测试页只显示摘要，完整统计保留下载。
- 通过 FFmpeg 导出 **MP4/GIF**，或按时间/步骤导出 PNG 快照。MP4 默认 1920px/30fps，GIF 默认 960px/20fps；有界逐帧编码，取消和失败清理临时文件。FFmpeg 需安装到 PATH；不含音频或 PPTX 原生动画。

## 绘制与兼容

网页和 VS Code 使用固定的 CanvasKit 0.42.0 标准包，优先使用 Worker、OffscreenCanvas 和 WebGL2。GPU 播放复用场景资源、只更新动画属性，不逐帧传递整幅 RGBA；保持请求的原生分辨率与效果，缓存超预算不降画质。保留主线程和 Skia 软件后端，VSIX 可离线使用。

原生位图采用 Skia CPU，PDF 页面由 SkPDF 生成；版本锁定的兼容处理保留原始 16 位颜色/透明度、精确页面尺寸和公式/艺术字 ActualText。SVG 与可编辑 PPTX 保留专用矢量导出器，Rust 继续负责排版与字形选择。静态导出不触发动画，旧 Vello CPU 与 krilla 已退出运行时依赖。

回归覆盖全部 97 个动画的浏览器参考、包含图表和公式的 32 页学术演示、首次播放、导航/取消/重试、渐进准备、固定文档版本、PDF 图像精度与文字语义，以及实际 VS Code 预览。CI 执行 Windows/Linux/macOS 原生测试、浏览器回归和五平台 wheel/VSIX 审计。

Python、Rust 和 VS Code 统一版本号 **0.6.0**，构建 Windows x64、Linux x64/ARM64、macOS Intel/Apple Silicon 包。沿用 PyPI 审核门禁，GitHub Release 使用同一批审核产物及校验和；Marketplace 继续手动上传。实际发行状态以[发布工作流](https://github.com/muxkin/LayMesh/actions/workflows/publish-pypi.yml)为准。
