# 属性增量预览：错误修复、页面复用与测量

本轮从 2026-10-15 开始，在已有语义增量实现上继续修改。工作区基线为 `d82b74bc5f8ec6aab3221ecd70d80e15b3b3583a`；保留本轮开始前的修改、原始附件和 v002 验证包。交付为本地 HTML 与 Linux x64 VSIX，未发布或安装到用户日常 VS Code 配置。

## 录像中的错误和其他页面刷新

录像中的 `Cannot read properties of undefined (reading 'map')` 来自编译结果接收和提交之间的竞态。播放器曾在收到 Worker 响应时就把页面加入可复用清单；响应随后可能因新输入而被丢弃。下一次编译因此把尚未提交的页面当作已知页面，返回 `unchanged`，而主页面的字体信息尚未建立，最终访问空值的 `map`。

现在每次更新先暂存页面记录，完成版本检查、结果验证和当前画面安装，再提交可复用清单。过期或失败响应不能进入该清单。错误保留上次成功结果，下载和放映继续经过最新版本屏障。新页面在这笔事务内部显示时不再等待同一事务的完成，避免形成循环等待。

原附件没有保存已验证的页面依赖，首次编辑只能保守处理所有页面。新的 `preview-state.json` 保存编译时实际读取的文件，且同时绑定源码、资源、字体、字体绑定、编译器 WASM 和各页载荷的摘要。任何一项不一致就忽略缓存。它允许打开附件后第一次修改封面颜色时直接只计算封面；另外五页保留原对象。共享 LCSS 被哪些页面读取，仍按这些页面的实际依赖重新验证；如果规则确实影响多页，这些页需要随后更新。

## 属性计算与绘图复用

样式读取记录区分布局输入和绘制属性。颜色变化不再使曲线生成函数、循环贡献和路径几何一起失效。普通矢量对象及普通组复用已完成的对象贡献，只更新受影响的填充、描边和透明度；同一组里相同的样式上下文共用一次外观解析。对象来源位置移动会重新绑定诊断来源，不因此重建无关几何。

普通锚点和路径查询可以继续复用几何；实际读取墨迹边界的查询保留样式依赖，因为描边宽度、可见填充等变化可能改变边界并影响后续分支。测试用完整编译对照检查这种依赖传播，而不是一概把样式变化当作不影响几何。

文字颜色与文字排版分开保存。字体、文字、尺寸和颜色分段边界相同时，改色复用排版、字形和字体请求；颜色分段的合并或拆分仍会重新排版，以保持原有字距和换行语义。字体数据或绑定变化会清理相关缓存。文字布局缓存有预算上限，并纳入可淘汰缓存统计。

函数、循环、分支、对象插入和删除继续使用同一编译会话的语义执行记录。新增迭代复用既有迭代；公式改变只使依赖公式的对象失效。绘图输出继续使用稳定对象身份和增量补丁，移动组不传输整组路径。复杂特效、箭头端点、裁剪和图片填充保留各自受影响的材料或子树求值；公式文字不走普通文字排版缓存。**属性增量不等于任何属性修改都完全不执行对象验证，也不等于所有复杂对象都具有相同的常数更新成本。**

## VS Code 的整份放映

新增协商能力 `incremental-document-v1` 和只规划目录的请求。原生响应分别报告目录依赖与页面依赖，兼容旧客户端的合并依赖字段。

放映编译进程和准备好的页面产物现在由预览面板持有，跨源码版本复用。每个准备版本独立管理取消和页面目录；页面复用检查实际源码、样式、资源、配置及转场，不把文档名称、顺序或页面别名当作页面内容变化。失效页优先回到原来的工作进程，保留其编译会话。打断后台准备会取消当前任务，保留进程供后续版本继续使用。

Webview 也保留已接受的页面产物。未变化页面收到的是带产物身份的引用，不重新发送完整页面 JSON。页面重命名或重排只重新建立目录；同一源码的新增别名直接引用已有产物。旧播放视图持有的页面在租约释放后清理，删除的页面和无引用资源及时淘汰。面板关闭时释放对应进程。

## 画面完成信号

本轮逐像素对照再次捕获到 Firefox 中 OffscreenCanvas 占位画面晚于完成信号到达的情况：求值和绘图数据正确，但即时画布曾短暂为空。离线源码预览改用带序号和页面版本的 ImageBitmap 交接，主页面安装对应位图后再跨过主窗口绘制更新。过期帧关闭并丢弃，动画帧沿用同一顺序交接。这样计时终点包括实际画面的交接，不以 Worker 提交绘图命令为终点。

GPU 上下文丢失时跳过的绘制不会确认成功；上下文恢复后重新调度尚未提交的版本。位图捕获或传输失败会释放未交付的位图，后续帧可以继续交接。这些错误路径由独立的帧交接测试验证。

`presentationConfirmed` 仍是经过即时像素对照的应用层完成信号，不是显示器扫描输出的硬件测量。后台未获得绘制机会的结果不能作为已确认画面进入验收。

## 测量口径

与 [v002 报告](semantic-preview-2026-10-15.zh-CN.md) 使用同一机器、场景、预热、50 次不同值修改和分位数算法。`.lay` 仍测第 2 页及含 1,536 条曲线的第 6 页的颜色、位置、文字、尺寸；LCSS 仍测标题颜色与全部 `.strand` 曲线颜色；laydoc 仍测改名、重排、新增和删除。新增与删除使用 100 次交替修改，分别保留 50 次。正式计时顺序执行，不与本任务的构建、回归或其他性能测试并行。

主机为 Linux x86_64、AMD Ryzen 7 8745H、16 个逻辑线程；完整环境记录见数据目录的 `environment.json`。浏览器使用自动选择的渲染后端，不把未记录的 GPU 状态推定为硬件或软件渲染。

浏览器为离线 `file://`、禁止 HTTP 网络、headless 1600×1000；VS Code 使用隔离的真实窗口、原生编译进程与 Webview，1440×1000、DPR 2，关闭周期性 CDP 诊断。自动化从编辑器提交源码修改开始计时，以应用确认的对应画面为终点；不是键盘硬件时戳或录屏估计。计时包含默认 30 毫秒输入合并窗口。浏览器排除两次预热，VS Code 排除一次预热。中位数取两个中间值平均，P95 取最近秩。

浏览器“整份同步”终点为全部页面编译完成；VS Code 终点还包含放映页面和资源接收确认。VS Code 的目录指标是宿主收到新目录，并非屏幕显示时间。浏览器使用附件嵌入字体，VS Code 使用同源项目和本机具名字体；两种图形环境分别报告。前后比较采用已保存的 v002 正式数据，不是交错执行的 A/B 测试。旧版使用当时的应用完成信号；本轮发现的位图交接竞态说明它不一定精确对应主窗口实际画面到达。新版完成信号另外经过即时像素核对。因此历史数值比较不应解释为显示器物理呈现时间的严格 A/B。

## 缓存与实现边界

缓存仍是有界的。编译器可淘汰派生数据、活动场景、字体和 WASM 保留容量分别统计；WASM 线性内存容量不等于当前活跃数据或浏览器进程总内存。原生放映的每个持久工作进程各自受缓存配置约束，多个进程的总占用需合并观察，不能把单进程预算说成整份应用的总内存上限。

依赖验证仍有入口遍历、结构核对和诊断整理成本。有限缓存下，后台页面的执行记录可能被淘汰，重新访问时需要恢复。检查信息、诊断和部分动画元数据继续按版本发送；没有把它们全部改成字段级补丁。WASM 取消沿用语义单元检查和分时重试，不保存完整解释器调用栈。这些成本会反映在下面的实测与原始指标中，不以单次纯编译计时替代端到端结果。
