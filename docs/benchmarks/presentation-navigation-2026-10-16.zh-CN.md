# 放映切页等待修复与对照测量

日期：2026-10-16。作品：原六页 LCSS 离线附件。修复前采用上一轮交付的 v003，修复后为 v004，均保留作品源码、字体、原生路径、样式、动画及转场。

## 原因与修复

切到第二页的诊断样本中，加载准备约 5,267 ms，其中约 5,106 ms 用于 146 次动画变换探测。原探测调用完整 frame_state，重复构造路径绘制和揭示动画的内容，再序列化到 JavaScript；缓存密度规划实际只需要矩阵。

增加同一内核的 transform_state，复用时间轴、变换原点、透视与揭示包装矩阵计算，省去绘图内容的克隆、路径裁剪和序列化。正式播放继续使用原完整采样。修复后的同一诊断样本为探测约 5 ms、加载准备约 223 ms；此处是单次热点定位，统计结果以下表为准。

CPU 后端另去除预加载时不可复用的整页临时栅格化，只保留安装阶段生成的绘制命令；正式显示仍以原分辨率绘制。GPU 后端继续预先建立需要的纹理缓存。

当前页推进与目标页加载不再等待整个相邻页预加载链。后台准备在探测计算单元之间让出执行权，前台操作可暂停后台工作，过期页面读取与准备请求不会继续安装或覆盖当前页。没有缓存层需要规划时直接跳过探测。

按用户反馈保留切页中的输入保护和按键重复保护：切页尚未完成时的额外方向键被忽略，不排队到随后自动执行。转场时长也保持作品原设置。

## 方法

每个环境分别测试 v003 与 v004，各 50 次有效切页，共 400 次。六页连续往返，交替使用左右、上下方向键；一次初始切页不计入统计。为隔离切页，前进前将当前页置于动画完成态，后退前置于初态。每次发送同一方向的 5 个键事件作为短串，确认最终只切到相邻目标页、保护生效且后续不补播。后退前的 seek(0) 可能让第一键先回到动画步边界，再由下一键切页；因此统计单位是一次短串触发的切页，不是每个按键各自的响应。

计时从短串第一个页面 keydown 事件进入正式处理器开始，直到目标页渲染完成、转场结束并跨过下一次浏览器绘制步骤。计时使用 DOM 键盘事件；浏览器另以 Playwright 真实键盘事件测试连续 ↓/→。这是浏览器确认画面的耗时，不是显示器扫描输出测量。

各浏览器为 1600×1000、DPR 1、headless，file:// 离线打开，禁止 HTTP 网络请求。VS Code 使用隔离开发配置、1440×1000 窗口、DPR 2，真实原生准备链与 webview；未安装到日常配置。计时与构建、其他验证隔离，不并行跑性能任务。修复前基线按 HTML 校验值复用；全部修复后样本采用最终制品。新旧版本按顺序运行，非随机交错 A/B。

浏览器插件的执行工具不可用，因此采用现有 Playwright 跨浏览器验证流程。CPU、内存、浏览器版本、实际渲染后端、原始每次调用及制品 SHA-256 见随附 JSON。各环境渲染尺寸与后端不同，横向绝对值不能直接代表引擎优劣。

## 扣除记录的转场时间

每个样本减去该次转场的实际执行时长后，再计算统计量。剩余包括资源准备、队列等待、绘制和呈现确认，并非纯 CPU 编译时间。保留转场意味着总切页仍会占用其设定的时长；本次重点消除额外数秒停顿。
